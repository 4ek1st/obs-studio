# Переход интерфейса OBS на WebView2

Статус на 28 сентября 2026: главное рабочее окно, создание и редактирование объектов, микшер, переходы, диалоги/настройки и дополнительные панели подключены к исходным контроллерам OBS. Проверенный набор и границы гибридного интерфейса перечислены в [coverage.md](coverage.md). Все функции каждой версии сторонних плагинов и каждого устройства не считаются автоматически проверенными.

## Цель и исходная точка

Пользователь поручил перенести весь интерфейс личного публичного форка OBS на WebView2 с сохранением возможностей. На первом этапе сохраняется знакомая структура оригинального интерфейса. Движок захвата, композиции, аудио и кодирования остаётся нативным: WebView2 предоставляет интерфейс управления.

Исходный коммит: `50530ce9046599e698c5d2068e4f053fae2318f6`, ветка `master`, версия исходников `33.0.0-beta4`. Это ветка разработки; установленный на компьютере официальный OBS имеет версию `32.2.1`. Сравнение поведения должно указывать, с какой именно версией оно выполнено.

`baseline-inventory.json` фиксирует 36 форм Qt Designer, 102 действия главного окна и 99 функций frontend API. Это статический перечень: динамические меню, свойства источников, установленные плагины и доступные аппаратные функции нужно проверять отдельно.

## Подтверждённое решение

Полное удаление Qt и совместимость с произвольными существующими панелями плагинов не достигаются одновременно простой заменой интерфейса. В `frontend/api/obs-frontend-api.h` функции `obs_frontend_add_dock_by_id` и `obs_frontend_add_custom_qdock` принимают соответственно QWidget и QDockWidget.

28 сентября 2026 года пользователь подтвердил: весь собственный интерфейс приложения переносим на WebView2, а для окон старых плагинов сохраняем Qt-совместимость. Пользователь также разрешил повторную установку необходимых компонентов сборки. Совместимость каждого стороннего плагина проверяется отдельно; сохранение Qt и frontend API обеспечивает необходимую основу.

## Другие ограничения равенства с официальным OBS

- Конфигурация форка без собственных идентификаторов приложений отключает интегрированный вход в Twitch, YouTube и Restream. Это подтверждено исходниками `frontend/cmake/feature-*.cmake` и результатом CMake. Копирование кода не выдаёт официальные ключи приложения. Поддержка RTMP сама по себе не доказывает сохранение входа в аккаунт.
- Браузерные источники OBS используют CEF для содержания сцен. Замена интерфейса на WebView2 не означает перенос браузерного источника, его рендера, аудио, cookies и интеграций.
- WebView2 задаёт Windows как платформу нового интерфейса. Другие платформы OBS не должны объявляться поддержанными новым интерфейсом без отдельной реализации.
- Производительность, HDR, доступность, управление с клавиатуры и совместимость плагинов требуют испытаний; их сохранение нельзя вывести из факта успешной компиляции.

## Предлагаемая архитектура

1. Нативный процесс OBS сохраняет управление жизненным циклом, источниками, сценами, выводом, сохранением данных и историей отмены. На этапе переноса существующее поведение вызывается через явные адаптеры.
2. WebView2 отображает локально поставляемые HTML/CSS/JavaScript. Ресурсы загружаются с фиксированного локального origin через virtual host mapping. Внешняя навигация не получает доступ к командам приложения.
3. Мост передаёт только явно разрешённые команды и проверяет типы, диапазоны и идентификаторы объектов. Ответы содержат request ID и ошибку. Состояние нативного OBS остаётся основным; frontend обновляется событиями и версионированными снимками.
4. Команды из WebView2 выполняются асинхронно в UI-потоке OBS. Нельзя открывать модальные окна синхронно внутри callback WebView2: это нарушает ограничения повторного входа WebView2.
5. Предпросмотр и program-view используют нативный GPU-рендер OBS в интегрированной поверхности. Поток не должен пережиматься или передаваться покадрово через JSON ради отображения в интерфейсе. Встраивание, порядок поверхностей, DPI, HDR и маршрутизация ввода проверяются отдельно.
6. Изменения сцен, источников и настроек должны сохранять существующие проверки, историю отмены и семантику сохранения. Прямой вызов libobs, обходящий эти механизмы, не считается равнозначным переносом.
7. Профили и коллекции сцен проверяются на изолированных копиях. При переходе на пользовательские данные сначала создаётся резервная копия и фиксируются хеши исходных файлов. WebView2 хранит собственные данные отдельно.

## Последовательность работ

1. Собрать и запустить исходную версию в отдельном portable-профиле; зафиксировать доступные модули и ограничения сборки.
2. Добавить WebView2 host и проверить загрузку локальных ресурсов, двусторонние команды, ошибки и завершение процесса.
3. Перенести главное окно и редактор сцен с проверкой предпросмотра, ввода и сохранения.
4. Перенести свойства, фильтры, расширенный звук и настройки, включая динамические поля плагинов.
5. Перенести остальные собственные диалоги и инструменты; проверить согласованный набор сторонних плагинов.
6. Сравнить вывод, задержки, CPU/GPU/память, обработку ошибок и сохранность данных. Подготовить отдельную сборку с воспроизводимыми инструкциями.

Каждый пункт остаётся незавершённым, пока нет соответствующей проверки. Наличие запасного окна Qt обеспечивает доступ к функции, но не считается завершением переноса этого окна на WebView2.

## Проверенные условия среды

Повторная установка VS Build Tools 2026 18.10.2 завершилась 28 сентября 2026 с кодом 0. Установлены MSVC 14.51, ATL, CMake 4.3.1 и Windows SDK 10.0.26100.0; WebView2 Runtime 153.0.4234.48. Старая VS 2022 сохранена.

Исходная сборка и сборка с WebView2 завершились успешно. Модули не отключались ради компиляции. Зависимости OBS/Qt/CEF загружены штатным CMake в .deps; старые каталоги не удалены. Последовательная сборка проектов обходит гонку вложенных x86-проектов OBS.

Первый этап включал локальное WebView2-окно, мост, сцены/источники/меню/управление и GPU-предпросмотр. После замечания пользователя реализованы инструменты создания/редактирования, микшер, Studio Mode и общий HTML-renderer оригинальных диалогов. Qt остаётся владельцем существующего поведения, модальности и интерфейсов плагинов; специальные нативные контролы встроены в HTML-окна.

Последний функциональный запуск: 163/163 проверки настоящего portable OBS, запись MP4 и завершение с кодом 0. Полный повторный запуск сравнил сохранённые источники/сцены/фильтры/профиль без различий. Добавлены native dialog/audio/drop tests и браузерные проверки взаимодействий. Ложное предупреждение Plugin Errors в режиме CoreOnly исправлено. Состояние личных данных и точные пределы этих доказательств приведены в [coverage.md](coverage.md).

На сценах интеграционного теста счётчик OBS показывает одну неосвобождённую аллокацию как с WebView2, так и в контрольном запуске только Qt. Причина пока не определена. Локальная запись проверена; стрим, полный набор сторонних плагинов, аппаратная матрица GPU/DPI/HDR и сравнение производительности требуют отдельных испытаний. Отсутствие всех регрессий не подтверждается конечным набором тестов.
