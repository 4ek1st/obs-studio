# OBS с интерфейсом WebView2

Ветка: **webview2-ui**. Основа: OBS `50530ce9046599e698c5d2068e4f053fae2318f6` (33.0.0-beta4).

В интерфейсе доступны создание и редактирование сцен/источников, микшер, переходы, Studio Mode, настройки, свойства, фильтры и штатные инструменты OBS. HTML вызывает существующие контроллеры OBS: проверки ввода, Undo, сохранение и обработчики плагинов остаются нативными.

## Запуск

Из корня клона:

~~~powershell
.\frontend\webview2\run-portable.ps1
~~~

По умолчанию используется **build_webview2_full/rundir/RelWithDebInfo**. Профиль находится внутри этой сборки, отдельно от установленного OBS. `-OnlyBundledPlugins` нужен только для диагностики. Обычно доступны плагины из portable-каталогов форка; автоматического копирования личных плагинов или сцен нет.

Кнопки **+** под сценами и источниками открывают штатное создание. Контекстное меню содержит полные действия OBS. F2 переименовывает строку, Delete удаляет выбранный объект; Ctrl/Shift позволяют выбрать несколько источников. Ctrl+Z отменяет действие, Ctrl+Y и Ctrl+Shift+Z повторяют его; фокус на ползунке громкости не блокирует эти команды. В текстовых полях сохраняется локальная отмена редактирования.

Раскладкой управляет исходный **OBSBasic/QMainWindow** с исходными **QDockWidget**. Панели можно закреплять по сторонам, разделять по горизонтали и вертикали, объединять во вкладки и выносить в отдельные окна. Перенос за заголовок, разделители, зоны закрепления и сохранение расположения выполняет штатный Qt-код OBS. Вынесенная панель возвращается перетаскиванием в область закрепления, двойным щелчком по заголовку или кнопкой **Закрепить**. Отдельной системной полосы над заголовком WebView-панели нет. Блокировка док-панелей использует исходные ограничения OBS.

## Что перенесено

- Главное окно: меню, сцены, дерево источников, видимость/блокировка, группы, порядок, инструменты, микшер, переходы, управление и статус.
- Предпросмотр и program используют настоящие GPU-поверхности OBS. Предпросмотр сохраняет редактирование мышью, трансформации и исходную обработку ввода; видео не передаётся через JSON.
- Микшер: штатный фейдер с Undo, mute, мониторинг, реальные уровни через obs_volmeter, расширенные свойства. Вертикальная компоновка использует отдельные полосы каналов, шкалу dB, категории и иконки исходного микшера.
- Studio Mode: обе поверхности, обычные/быстрые переходы, создание/настройка быстрых переходов и T-bar.
- Собственные диалоги: HTML представляет существующие поля, кнопки, списки, таблицы, вкладки и динамические свойства. Исходный Qt-диалог остаётся владельцем модальности и сохранения.
- Основные панели: отдельный HTML-документ внутри исходного QDockWidget в закреплённом и плавающем состоянии. Исходные содержимое, контроллеры, владение и сохранение Qt layout сохранены.
- Перетаскивание файлов/ссылок/текста поступает штатному обработчику импорта OBS. Пути файлов принимаются только от настоящих объектов WebView2, а не из произвольного JSON.
- Тема, изменение масштаба, размеры окна, клавиши, трей, подтверждения остановки/выхода и восстановление штатного окна при отказе WebView2.

Qt/frontend API, CEF браузерных источников, libobs, кодировщики и штатные модули сохранены.

## Граница между HTML и нативным интерфейсом

Главное окно, его меню/status bar и механизм док-панелей остаются нативными; WebView2 рисует центральную область и содержимое основных панелей. GPU-превью, системные file/color/font pickers, Qt popup menus, плитки выбора типа источника, редакторы горячих клавиш, специальные слайдеры, перетаскиваемые списки и неизвестные custom-контролы используют оригинальную нативную поверхность внутри соответствующего окна. Они остаются работающими и сохраняют исходные callbacks. Это гибридный интерфейс; Qt не удалён.

Наличие Qt и frontend API не гарантирует совместимость каждого стороннего DLL. Личный OBS здесь имеет версию 32.2.1, исходники форка — 33.0.0-beta4. Установленные сторонние DLL не переносились автоматически. Для входа в Twitch/YouTube/Restream нужны собственные OAuth-параметры приложения.

Полная матрица реализации и проверок: [coverage.md](coverage.md).

## Сборка Windows x64

Нужны VS Build Tools 2026, MSVC x64/x86, ATL, CMake, Windows SDK и Microsoft Edge WebView2 Runtime. Здесь использованы VS 18.10.2, MSVC 14.51, CMake 4.3.1, SDK 10.0.26100.0 и Runtime 153.0.4234.48.

~~~powershell
cmake --preset windows-x64 -B build_webview2_full -DENABLE_WEBVIEW2_INTEGRATION_TESTS=OFF
cmake --build build_webview2_full --config RelWithDebInfo --parallel 1 -- /p:CL_MPCount=4 /verbosity:minimal
~~~

Зависимости OBS загружаются штатным CMake. WebView2 SDK 1.0.4191.47 закреплён SHA-256 в `cmake/windows/webview2.cmake`. Последовательная сборка проектов обходит наблюдавшуюся гонку вложенных x86-проектов.

После полной сборки для изменений только frontend можно использовать `--target obs-studio -- /p:BuildProjectReferences=false`. Первую сборку этот способ не заменяет.

## Проверка разработки

Native tests: `test/webview2`, `test/webview2/audio-tests`, `test/webview2/drop-tests`, `test/webview2/window-list-tests`, `test/webview2/preview-mask-tests`. JavaScript:

~~~powershell
node test/webview2/client-test.mjs
node test/webview2/dialog-layout-test.mjs
node test/webview2/dialog-scrollbar-test.mjs
node test/webview2/drop-client-test.mjs
~~~

Интеграционный тест включается только через **-DENABLE_WEBVIEW2_INTEGRATION_TESTS=ON**. Запуск требует одновременно **--webview2 --portable --webview2-self-test --only-bundled-plugins**. Использовать только одноразовый portable-каталог: тест создаёт сцены/источники/фильтры, меняет тестовые настройки, пишет короткую локальную запись из цветовых источников и завершает OBS.

Отчёты внутри portable-профиля:

- `config/obs-studio/webview2-integration.json` — проверки главного окна, audio, диалогов и записи.
- `config/obs-studio/test-recordings/output-workflow-*.json` — файл записи, кадры, отмена/подтверждение остановки.
- `config/obs-studio/webview2-persistence-fixture.json` — сохранённое нативное состояние.
- `config/obs-studio/webview2-persistence.json` — сравнение после запуска с дополнительным **--webview2-persistence-test**.

`OBS_WEBVIEW2_TEST_ARTIFACTS` задаёт каталог PNG из реального WebView2 CapturePreview. Такие PNG содержат HTML; встроенные нативные GPU-поверхности и custom-контролы в них не захватываются. `OBS_WEBVIEW2_TRACE_GEOMETRY=1` сохраняет рядом диагностическую геометрию HWND/controller.

Изолированный тест производительности Settings и защиты от создания лишних нативных окон: [dialog-performance-tests](../../test/webview2/dialog-performance-tests/README.md). Опциональный `OBS_WEBVIEW2_TRACE_PERFORMANCE` принимает абсолютный путь JSONL-файла и записывает этапы запуска host и длительность снимков, без значений полей и паролей.

Для проверки захвата можно собрать отдельное графическое приложение из `test/webview2/capture-tests`. Пока оно работает, установите `OBS_WEBVIEW2_CAPTURE_FIXTURE=OBS capture QA target:OBSWebViewCaptureFixture:obs-capture-fixture.exe`. Полный прогон проверит Game Capture и Window Capture на реальном изображении 640×360, а также свойства Application Audio и Display Capture. Дополнительный флаг `--webview2-capture-test` запускает только эту часть и сохраняет `capture-report.json` в каталоге артефактов.

В capture-проверке PNG с суффиксом `-composed` содержит реальное изображение тестового диалога вместе с GPU-превью. Оно сохраняется только при видимом собственном тестовом окне; одноразовый диалог ненадолго поднимается поверх остальных окон. JSON дополнительно сравнивает Qt-координаты с origin HWND и размеры swapchain с client area. Пользовательская установка для этого не используется.

**Обычная запускаемая сборка компилируется с интеграционными тестами OFF.**

Архитектура и исходные требования: [migration-design.md](migration-design.md).
