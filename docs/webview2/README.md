# OBS с интерфейсом WebView2 — текущее состояние

Ветка: **webview2-ui**. Основа: OBS 50530ce9046599e698c5d2068e4f053fae2318f6 (33.0.0-beta4).

Это первый работающий этап переноса интерфейса. Полный перенос OBS на WebView2 ещё не выполнен.

## Уже реализовано

- Окно WebView2 с локальными HTML/CSS/JavaScript, сценами, верхними меню, списком источников и кнопками управления.
- Состояние и команды настоящего OBS. Нативный SourceTree остаётся владельцем выделения.
- Предпросмотр через нативный GPU-рендер OBS; кадры не передаются через JSON. Размер пересчитывается из CSS viewport в координаты Qt и обновляется при изменении окна.
- Версионированный мост с ID запросов, таймаутами, проверкой origin и разрешённых команд. Старые команды отклоняются при смене сцены, профиля, вывода или выделения, включая группы.
- Qt и frontend API сохранены для плагинов. CEF браузерных источников сохранён.
- Исправлено исходное ложное предупреждение Plugin Errors в режиме CoreOnly: после успешной загрузки встроенных модулей PluginManager теперь сообщает Success.

## Запуск существующей сборки

Из корня клона:

~~~powershell
.\frontend\webview2\run-portable.ps1
~~~

Скрипт запускает build_webview2\rundir\RelWithDebInfo\bin\64bit\obs64.exe с флагами --portable --webview2. Portable-данные находятся внутри каталога сборки. Для диагностики только со встроенными модулями добавьте **-OnlyBundledPlugins**. По умолчанию скрипт не запрещает загрузку сторонних плагинов из portable-каталогов.

При запуске с --webview2 закрытие нового окна проходит через штатное завершение OBS; отмена подтверждения оставляет интерфейс открытым. Кнопка настроек виртуальной камеры получает видимую подпись из нативного accessibleName/tooltip.

В исходном окне OBS новое окно открывается через **Инструменты → WebView2**. Оригинальное окно остаётся доступным на протяжении переноса.

## Сборка Windows x64

Нужны VS Build Tools 2026, MSVC x64/x86, ATL, CMake, Windows SDK 10.0.26100.0 и Microsoft Edge WebView2 Runtime. В этой среде установлены VS 18.10.2 / MSVC 14.51 / CMake 4.3.1 / Runtime 153.0.4234.48.

~~~powershell
cmake --preset windows-x64 -B build_webview2 -DENABLE_WEBVIEW2_INTEGRATION_TESTS=OFF
cmake --build build_webview2 --config RelWithDebInfo --parallel 1 -- /p:CL_MPCount=4 /verbosity:minimal
~~~

CMake скачивает официальные зависимости OBS. WebView2 SDK 1.0.4191.47 закреплён SHA-256 в cmake/windows/webview2.cmake. Последовательная сборка проектов обходит наблюдавшуюся гонку вложенных x86-проектов OBS.

Для интегрированного OAuth Twitch/YouTube/Restream нужны собственные параметры приложений. Эта dev-сборка не содержит ключей официального OBS.

- Проверка DOM на отдельной браузерной фикстуре: выделение, меню, кнопки, удержание фокуса; ошибок JavaScript не обнаружено. Она не заменяет проверку нативного приложения.
- Хеши 22 исходных личных файлов конфигурации не изменились.
- Первый интеграционный запуск на чистом portable-профиле завершился с 0 неосвобождённых аллокаций; повторный запуск на созданных тестом сценах — с 1. Ранее Qt-only сравнение на тестовых сценах также давало 1. Причина не локализована; отсутствие утечек для всех сценариев не подтверждено.

Интеграционный тест компилируется только с **-DENABLE_WEBVIEW2_INTEGRATION_TESTS=ON** и требует одновременно **--webview2-self-test --portable --only-bundled-plugins --webview2**. Запускать только в отдельном каталоге с одноразовыми данными: тест создаёт сцены/источники и меняет настройку подтверждения выхода. Отчёт: config/obs-studio/webview2-integration.json. Дополнительный флаг **--webview2-lifecycle-only** проверяет запуск/закрытие без команд; **--webview2-qt-baseline** пропускает WebView2 для сравнения с Qt.
