# Покрытие интерфейса и проверок

Проверено 28 сентября 2026 года. Исходники OBS 33.0.0-beta4; личная установленная версия для сравнения — 32.2.1. Полный исходный перечень: [baseline-inventory.json](baseline-inventory.json). Он содержит 36 форм, 102 действия главного окна и 99 функций frontend API; это не число независимо испытанных сценариев.

## Проверенные результаты

- Настоящий portable OBS, финальный прогон: **239 проверок, 0 ошибок**. Включены размеры семи диалогов, запись, меню/GPU-маска, плавающая панель и её жизненный цикл, визуальный audio fixture, сохранение состояния и сравнение оформления выбора источника с тем же нативным окном. Отчёт и изображения: `.superpowers/quality-regressions/final/`.
- Повторный запуск для проверки сохранения: **23 проверки пройдены**, native state восстановлено без различий.
- Native dialog bridge: **64 проверки**. Включены настоящие Qt-модели, делегаты, F2/Enter/Escape, QObject invalidation, palette/font, AbsoluteSlider, dock lifecycle, полностью нативная область и нативное оформление scrollbar/рамок с сохранением прозрачных отступов.
- Audio adapter: **43 проверки**; перечисление окон Windows: **5 проверок**.
- Реальные окна свойств захвата: **46 проверок пройдены**. Game Capture и Window Capture получили изображение отдельного графического fixture размером **640×360**; проверены начальные координаты HWND, размеры swapchain и отверстие в маске диалога.
- Браузерные действия проверены отдельно от native integration: ввод/blur, combo, число 854, checkbox, model edit, кнопки, right-click rename, перемещение и изменение ширины панелей, reload/persistence; ошибок JavaScript не зафиксировано.
- Диагностика нашла controller 100×30 при HWND 981×730; отложенная синхронизация после Qt Show/Resize исправила это. Финальный реальный CapturePreview имеет полный размер окна.

Локальные полные отчёты и изображения сохраняются в `.superpowers/sdd/2026-09-28-webview2-functional-parity/`, `.superpowers/quality-regressions/` и тестовом portable config. Полный интеграционный отчёт — `config/obs-studio/webview2-integration.json` соответствующего portable stage; код завершения процесса сам по себе не заменяет проверку массива `checks`. В Git входят тесты, а не личные настройки и записи.

## Исправленные регрессии и уровень доказательств

- **Браузерный fixture:** проверяет HTML-обработчики, перетаскивание панели, вертикальную компоновку микшера и ввод scrollbar. Его данные заданы тестом; такой результат не доказывает работу OBS, аудиоустройств или GPU-захвата.
- **Настоящий OBS:** финальный прогон использует исходные сцены, контроллеры, docks и output. Для изображения микшера источник добавлен в активную сцену, подаёт stereo PCM и найден по UUID в нативном VolControl и production snapshot. Панель на время захвата показана и присоединена; после теста источник удаляется, положение панели, ориентация и размер окна восстанавливаются.
- **Native HWND и GPU:** при первом открытии Game Capture Qt задавал `(11, 11)`, а HWND оказывался в `(22, 22)` из-за смены нативного родителя. Синхронизация QWindow относительно нового родителя исправила координаты без замены HWND/swapchain. Повторный реальный прогон подтвердил `(11, 11)` при первом открытии и после изменения размера. Проверка использует координаты относительно диалога; прежнее сравнение через `mapToGlobal()` могло повторять ошибочную позицию HWND.
- **Меню и плавающие панели:** браузерная маска закрывает только меню или drag ghost; открытая часть GPU-превью остаётся видимой. Нативный helper проверяет маршрутизацию попаданий, интеграция — включённое состояние и сохранение display. Команды плавающей панели в интеграционном helper проходят через её нативный `messageReceived`; это не запись пользовательских кликов по HTML.
- **Изображения:** `CapturePreview` показывает реальный Chromium, а нативный VolControl снимается отдельно. Снимок `QScreen::grabWindow(dialogHWND)` давал устаревшую составную картинку и не используется как доказательство положения GPU. Положительный итог автоматических проверок не означает завершённую визуальную проверку всех окон.
- **Оформление панелей:** визуальное сравнение того же Source Picker в Qt и WebView2 выявило превращение отступов `frameWidth` в толстую сплошную границу. Теперь передаётся рисунок исходного QStyle с прозрачными отступами. Новый native regression, JS-проверка и просмотр финального изображения подтвердили тонкие границы без серых полос.

## Известные границы

- Интерфейс гибридный: GPU, Qt popup menus, OS pickers и custom/native islands перечислены в [README.md](README.md). Qt не удалён; ссылка на старое окно сама по себе не считается переносом функции.
- Полный набор сторонних DLL пользователя под OBS 33 не запускался. Сохранены Qt/frontend API и исходные механизмы загрузки, но бинарная совместимость с установленным OBS 32 требует проверки конкретных версий плагинов.
- Live stream, replay buffer, virtual camera в принимающем приложении, все устройства захвата, VST, HDR, смена мониторов с разным DPI и производительность всей системы не проходили полную практическую матрицу. Для них сохранены исходные реализации; успешная локальная запись не доказывает весь этот набор.
- Вход Twitch/YouTube/Restream требует собственных OAuth-параметров форка. Официальные секреты OBS в исходниках отсутствуют.
- Remux, import/export, wizard и остальные редкие инструменты доступны через исходные actions и общий renderer; отдельный end-to-end сценарий каждого инструмента ещё не выполнялся.
- Physical Explorer→WebView2 file drop не проверялся мышью. Native/COM и JS проверки не следует выдавать за такую проверку.
- CapturePreview отображает HTML, но не вложенный native GPU/custom HWND. Полностью пустая область на таком PNG не доказывает отсутствие native preview на экране.
- На повторно используемых тестовых сценах OBS сообщает одну неосвобождённую аллокацию; контрольный Qt-only запуск ранее показывал ту же величину. Причина не локализована.
- Новые вспомогательные подписи пока русские; штатные строки приходят из текущей локализации OBS. Меню HTML используют маску над native preview: перекрывается только область меню, GPU-дисплей остаётся видимым и включённым.

## Сохранность личной установки

Тесты и нормальная сборка используют отдельный portable-каталог. Личная установка, процессы, профили и коллекции сцен не заменялись. С исходными хешами совпадают все проверенные личные профили/коллекции/основные настройки. Четыре отличающихся файла из полного набора 22 относятся к cache/browser preferences и каталогу rtmp-services активной личной установки; они не копировались и не восстанавливались инструментами этой задачи.

После проверки обычного запуска сборки с `ENABLE_WEBVIEW2_INTEGRATION_TESTS=OFF` обновлён только portable-форк: `obs64.exe`, `obs.dll`, WebView2 assets и Open Sans — 13 файлов. Перед заменой форк штатно завершён и сохранена резервная копия файлов и всего его config. Хеши всех 566 файлов config до и после установки совпали; хеши установленных файлов совпали с подготовленным пакетом. Форк запущен повторно. Тестовые сцены и настройки в рабочий профиль не копировались.
